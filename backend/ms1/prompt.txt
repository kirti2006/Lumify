Create a production-grade Express application with TypeScript for the Lumify MS-1 API Gateway.
Make sure to follow these rules:

1. We will keep separate folders for architectural layers.
The path structure will be: src/controllers, src/services, src/routes, src/middlewares, src/database, src/utils, src/config.

2. Inside these folders, follow naming conventions:
- Routes: `<name>.routes.ts`
- Controllers: `<name>.controller.ts`
- Services: `<name>.service.ts`

3. Inside the src folder, we will have:
config/
controllers/
database/
middlewares/
routes/
services/
utils/
app.ts
server.ts

4. Use functional programming for route handlers and services. Use classes for specific use-cases like custom error handling.

5. Use winston logger for logging (found in src/config/logger.ts). Use this logger everywhere to log execution flows and errors. Never use console.log directly.

6. API response convention:
Success: { success: true, message: "...", data: {...} }
Error: { success: false, message: "...", error: "..." }

7. Create custom error classes (e.g., AppError) and throw them at required places.

8. The error handling will be done centrally in an error-handling middleware.

9. Use `express-async-handler` or a custom utility to wrap async route handlers to avoid try-catch blocks everywhere.

10. Use zod for input validation. Infer TypeScript types from zod schemas.

11. Use Drizzle ORM with Neon (Postgres) for the database. Schema is kept in `src/database/schema.ts`. Use drizzle-kit for migrations.

12. Environment variables are managed globally and loaded from a `.env` file via `dotenv`.

13. Use Redis for caching and rate limiting (Upstash Redis).

14. Keep JWT based authentication (Access + Refresh tokens). Passwords must be hashed using bcrypt.

15. Setup these middlewares: cors, helmet, express.json, and morgan for HTTP request logging.

16. Expose a health check API at "/health" or "/api/v1/health".

17. MS-1 proxies specific AI-related routes to MS-2. Keep the proxy logic isolated and well-handled.
